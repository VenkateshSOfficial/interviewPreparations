# JAVASCRIPT THEORY

## 1. Difference between Java and JavaScript

**Answer:**

| Feature | Java | JavaScript |
|---------|------|-----------|
| **Type** | Compiled language | Interpreted language |
| **Typing** | Statically typed | Dynamically typed |
| **Execution** | Server-side (JVM) | Primarily client-side (browser) |
| **OOP** | Class-based | Prototype-based (Object model) |
| **Syntax** | Similar but stricter | More flexible |
| **Memory** | Requires more resources | Lightweight |
| **Use Cases** | Enterprise apps, backends | Web development, DOM manipulation |
| **File Extension** | .java | .js |
| **Compilation** | Needs compilation to bytecode | No compilation needed |

**Key Interview Point:** "JavaScript is a lightweight, dynamically typed language designed for browser environments, while Java is a robust, statically typed language used for enterprise applications on the server side."

## 2. var, let & const

**Answer:**

### Comparison Table

| Feature | var | let | const |
|---------|-----|-----|-------|
| **Scope** | Function scope | Block scope | Block scope |
| **Hoisting** | Hoisted (undefined) | Hoisted (TDZ) | Hoisted (TDZ) |
| **Re-declaration** | Allowed | Not allowed | Not allowed |
| **Re-assignment** | Allowed | Allowed | Not allowed |
| **Best Practice** | Avoid | Use by default | Use when value doesn't change |

### Code Examples

```javascript
// var - Function Scoped
function test() {
  var x = 1;
  if (true) {
    var x = 2; // Same variable!
  }
  console.log(x); // 2
}

// let - Block Scoped
function test2() {
  let y = 1;
  if (true) {
    let y = 2; // Different variable!
  }
  console.log(y); // 1
}

// const - Block Scoped (no re-assignment)
const z = 1;
z = 2; // TypeError: Assignment to constant variable
```

### Temporal Dead Zone (TDZ)

```javascript
console.log(a); // ReferenceError - let and const are in TDZ
let a = 5;

console.log(b); // undefined (var is hoisted with undefined)
var b = 10;
```

### Why var is still used (outdated approach)

- **Legacy code:** Older JavaScript projects use var extensively
- **Backward compatibility:** Some browsers still require it
- **Interview context:** Shows understanding of JavaScript evolution

**Best Practice:** Always use `const` by default, `let` when you need to re-assign, and avoid `var` entirely in modern code.

## 3. Hoisting

**Answer:**

Hoisting is JavaScript's behavior of moving declarations to the top of their scope before code execution.

### How It Works

```javascript
// Variable Hoisting
console.log(x); // undefined (not ReferenceError)
var x = 5;
console.log(x); // 5

// Same as:
// var x;
// console.log(x); // undefined
// x = 5;
// console.log(x); // 5
```

### Function Hoisting

```javascript
// Function declarations are fully hoisted
console.log(add(2, 3)); // 5

function add(a, b) {
  return a + b;
}

// Function expressions are NOT hoisted
console.log(multiply(2, 3)); // TypeError: multiply is not a function

var multiply = function(a, b) {
  return a * b;
};
```

### let and const with Temporal Dead Zone (TDZ)

```javascript
console.log(y); // ReferenceError
let y = 10;

// They ARE hoisted but in TDZ (Temporal Dead Zone)
// Can't access them until declaration is reached
```

### Can Classes be Hoisted?

**Answer:** Classes are hoisted but NOT initialized. They remain in TDZ until the class declaration is reached.

```javascript
console.log(new MyClass()); // ReferenceError: Cannot access 'MyClass' before initialization

class MyClass {
  constructor() {
    this.name = "Test";
  }
}

// This works because class expressions are not hoisted
const MyClass2 = class {
  constructor() {
    this.name = "Test";
  }
};
```

## 5. Types of Functions & Hoisting

**Answer:**

### Types of Functions

```javascript
// 1. Function Declaration
function add(a, b) {
  return a + b;
}

// 2. Function Expression
const multiply = function(a, b) {
  return a * b;
};

// 3. Arrow Function (ES6)
const subtract = (a, b) => a - b;

// 4. Callback Function
function processArray(arr, callback) {
  return arr.map(callback);
}
processArray([1, 2, 3], (num) => num * 2);

// 5. Anonymous Function
setTimeout(function() {
  console.log("Executed after 1 second");
}, 1000);

// 6. Immediately Invoked Function Expression (IIFE)
(function() {
  console.log("Runs immediately");
})();

// 7. Generator Function
function* generator() {
  yield 1;
  yield 2;
}
```

### Which Type Avoids Hoisting?

**Answer:** Function expressions and arrow functions are NOT hoisted.

```javascript
// NOT hoisted - Error
console.log(multiply(5, 2)); // TypeError
const multiply = (a, b) => a * b;

// Hoisted - Works
console.log(add(5, 2)); // 7
function add(a, b) {
  return a + b;
}
```

### When to Use Callback Functions?

```javascript
// Asynchronous operations
fetch(url).then(response => response.json()); // Callback

// Array methods
[1, 2, 3].forEach(num => console.log(num)); // Callback

// Event handlers
button.addEventListener('click', () => doSomething()); // Callback

// Delayed execution
setTimeout(() => console.log("After 2 seconds"), 2000); // Callback
```

### Actual Use of Arrow Functions in Callbacks

**Answer:**

1. **Concise Syntax**
```javascript
// Without arrow
[1, 2, 3].map(function(x) { return x * 2; });

// With arrow - cleaner
[1, 2, 3].map(x => x * 2);
```

2. **Lexical this Binding** (Most important!)
```javascript
// Problem with regular function
const person = {
  name: "John",
  greetings: ["Hello", "Hi"],
  print() {
    this.greetings.forEach(function(greeting) {
      console.log(greeting + " " + this.name); // undefined (this refers to window)
    });
  }
};

// Solution with arrow function
const person2 = {
  name: "John",
  greetings: ["Hello", "Hi"],
  print() {
    this.greetings.forEach(greeting => {
      console.log(greeting + " " + this.name); // "Hello John" (this preserved)
    });
  }
};
```

## 7. Limitations of Arrow Functions

**Answer:**

```javascript
// 1. No 'this' binding - uses lexical this
const obj = {
  name: "John",
  regularFunc() {
    console.log(this.name); // "John"
  },
  arrowFunc: () => {
    console.log(this.name); // undefined (this from outer scope)
  }
};

// 2. No 'arguments' object
const arrowFunc = () => {
  console.log(arguments); // ReferenceError
};

// 3. Cannot be used as constructor
const ArrowConstructor = () => {};
new ArrowConstructor(); // TypeError

// 4. No 'prototype' property
const arrowFunc2 = () => {};
console.log(arrowFunc2.prototype); // undefined

// 5. Cannot be used as generator
const arrowGen = () => { // SyntaxError
  yield 1;
};
```

### Why Arrow Functions is Alternative to Function Expression?

1. **Cleaner Syntax**
2. **Lexical this binding** (solves context issues)
3. **Better for callbacks** (especially in event handlers)
4. **Implicit return** for single expressions

```javascript
arr.forEach(x => console.log(x)); // Executes for each element
arr.map(x => x * 2); // [2, 4, 6, 8, 10]
arr.filter(x => x > 2); // [3, 4, 5]
arr.reduce((acc, x) => acc + x, 0); // 15
```

## 9. OOPS in JavaScript

**Answer:**

```javascript
// 1. Encapsulation
class BankAccount {
  #balance = 0; // Private field

  constructor(initialBalance) {
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

// 2. Inheritance
class Animal {
  speak() {
    console.log("Making a sound");
  }
}

class Dog extends Animal {
  speak() {
    console.log("Woof!");
  }
}

// 3. Polymorphism
class Cat extends Animal {
  speak() {
    console.log("Meow!");
  }
}

const dog = new Dog();
const cat = new Cat();
dog.speak(); // "Woof!"
cat.speak(); // "Meow!"
```

### Do We Have Compile-Time Polymorphism (Method Overloading)?

**Answer:** NO. JavaScript does not support method overloading. If you define two methods with the same name, the second one overwrites the first.

```javascript
// Method Overloading NOT supported
class Calculator {
  add(a, b) {
    return a + b;
  }

  add(a, b, c) { // This overwrites the first add() method
    return a + b + c;
  }
}

const calc = new Calculator();
calc.add(2, 3); // Argument c is undefined - returns NaN

// Workaround: Use default parameters or rest parameters
class Calculator2 {
  add(...args) {
    return args.reduce((acc, val) => acc + val, 0);
  }
}

calc2.add(2, 3); // 5
calc2.add(2, 3, 4); // 9
```

## 10. Types of Inheritance Supported by JS

**Answer:**

```javascript
// 1. Prototype-based Inheritance
const parent = {
  greet() {
    return "Hello from parent";
  }
};

const child = Object.create(parent);
child.greet(); // "Hello from parent"

// 2. Constructor-based Inheritance
function Parent(name) {
  this.name = name;
}

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}

Child.prototype = Object.create(Parent.prototype);
const child2 = new Child("John", 10);

// 3. Class-based Inheritance (ES6)
class ParentClass {
  constructor(name) {
    this.name = name;
  }
  greet() {
    return "Hello";
  }
}

class ChildClass extends ParentClass {
  constructor(name, age) {
    super(name);
    this.age = age;
  }
}

const child3 = new ChildClass("Jane", 12);

// 4. Mixins/Composition
const canEat = {
  eat() { console.log("Eating"); }
};

const canWalk = {
  walk() { console.log("Walking"); }
};

const person = { ...canEat, ...canWalk };
person.eat(); // "Eating"
person.walk(); // "Walking"

// 5. Delegation (Prototype Chain)
const obj1 = { a: 1 };
const obj2 = Object.create(obj1);
obj2.b = 2;
console.log(obj2.a); // 1 (delegated to obj1)
```

## 12. Prototypes in JavaScript & Object.assign

**Answer:**

### Prototypes

```javascript
// Every function has a prototype property
function Person(name) {
  this.name = name;
}

// Add method to prototype
Person.prototype.greet = function() {
  return `Hello, I'm ${this.name}`;
};

const person1 = new Person("John");
const person2 = new Person("Jane");

person1.greet(); // "Hello, I'm John"
person2.greet(); // "Hello, I'm Jane"

// Check prototype chain
console.log(person1.__proto__ === Person.prototype); // true
console.log(person1.hasOwnProperty("name")); // true
console.log(person1.hasOwnProperty("greet")); // false (in prototype)
```

### Prototype Chain

```javascript
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  console.log(this.name + " speaks");
};

function Dog(name) {
  Animal.call(this, name);
}

Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

const dog = new Dog("Buddy");
dog.speak(); // "Buddy speaks" (inherited from Animal)
```

### Object.assign()

```javascript
// Shallow copy
const source = { a: 1, b: { c: 2 } };
const target = {};
Object.assign(target, source);

target.a = 99; // Doesn't affect source
target.b.c = 99; // AFFECTS source (shallow copy)

// Merge multiple objects
const obj1 = { a: 1 };
const obj2 = { b: 2 };
const obj3 = { c: 3 };
const merged = Object.assign({}, obj1, obj2, obj3);
// { a: 1, b: 2, c: 3 }

// Later values override earlier ones
const result = Object.assign({}, { x: 1 }, { x: 2 });
// { x: 2 }
```

## 13. Classes & Constructors

**Answer:**

```javascript
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hello, I'm ${this.name}`;
  }

  static info() {
    return "This is a Person class";
  }
}

const person = new Person("John", 30);
```

### Do Constructors Have Return Statements?

**Answer:** Constructors CAN have return statements, but with specific behavior:

```javascript
// 1. Returning object - returns the object instead of this
class Person {
  constructor(name) {
    this.name = name;
    return { name: "Different", age: 100 }; // Returns this object!
  }
}

const p1 = new Person("John");
console.log(p1); // { name: "Different", age: 100 }
console.log(p1 instanceof Person); // false

// 2. Returning primitive - ignored, returns 'this'
class Person2 {
  constructor(name) {
    this.name = name;
    return "Ignored"; // Primitive return is ignored
  }
}

const p2 = new Person2("Jane");
console.log(p2.name); // "Jane" (returns this)
console.log(p2 instanceof Person2); // true

// 3. No return statement - implicitly returns 'this'
class Person3 {
  constructor(name) {
    this.name = name;
    // No return - implicitly returns this
  }
}

const p3 = new Person3("Bob");
console.log(p3.name); // "Bob"
```

**Best Practice:** Don't explicitly return from constructors. Return objects only when not using classes.

## 14. Sync vs Async

**Answer:**

### Synchronous Execution

```javascript
// Code executes line by line, each statement waits for previous
console.log("Start");

function slowFunction() {
  let sum = 0;
  for (let i = 0; i < 1000000000; i++) {
    sum += i;
  }
  return sum;
}

const result = slowFunction();
console.log("End");

// Output: Start -> (waits for slowFunction) -> End
// Browser freezes while slowFunction executes
```

### Asynchronous Execution

```javascript
console.log("Start");

setTimeout(() => {
  console.log("Executed after 1 second");
}, 1000);

console.log("End");

// Output: Start -> End -> Executed after 1 second (after 1 second)
```

### Why Async is Important

- **Non-blocking:** UI doesn't freeze
- **Better UX:** Application stays responsive
- **Handles I/O:** Network requests, file reading

## 15. Asynchronous Programming in JavaScript

**Answer:**

**See event-loop.md for detailed explanation**

### How is it Achieved?

```javascript
// 1. Callbacks
function fetchData(callback) {
  setTimeout(() => {
    callback("Data loaded");
  }, 1000);
}

fetchData((data) => console.log(data));

// 2. Promises
function fetchData2() {
  return new Promise((resolve, reject) => {

      resolve("Data loaded");
    }, 1000);
  });

fetchData2().then(data => console.log(data));

// 3. Async/Await
async function getData() {
  const data = await fetchData2();
  console.log(data);
}

getData();
```

### Non-Blocking

```javascript
// Blocking code
let result = slowSyncFunction(); // Waits here

// Non-blocking code
slowAsyncFunction().then(result => {
  // Do something with result
});
console.log("This runs immediately, not waiting");
```

### How Does JS Support Multi-Threading?

**Answer:** JavaScript is single-threaded, but it appears to do multiple things at once through:

1. **Event Loop:** Manages task queues
2. **Web APIs:** Browser features (setTimeout, fetch) run in separate threads
3. **Callback Queue:** Stores callbacks ready to execute
4. **Microtask Queue:** Higher priority queue for Promises

```javascript
const dateJson = '{"date":"2023-01-01"}';
```

## 19. Exports and Imports

**Answer:**

```javascript
// CommonJS (Older - used in Node.js)
// Export
module.exports = function() { return "Hello"; };
module.exports = { name: "John" };

// Import
const greeting = require('./greeting');
const { name } = require('./module');

// ES Modules (Modern - used in browsers)
// Named Export
export const add = (a, b) => a + b;
export const subtract = (a, b) => a - b;

// Default Export
export default function greet() {
  return "Hello";
}

// Import
import greet from './greet'; // Default import
import { add, subtract } from './math'; // Named import
import greet as defaultGreet, { add } from './module'; // Mixed

// Re-export
export { add, subtract } from './math';
export { default as greet } from './greet';
```

### Why Do We Use Default Keyword in Exports?

```javascript
// Default Export
export default function greet() {
  return "Hello";
}

// Benefits:
// 1. Only one default per file
// 2. Can import without naming
import greet from './module'; // Works!

// 3. Cleaner syntax for main export
// 4. Can import with any name
import welcome from './module'; // Also works!

// Without default
export function greet() { }
// Must import with exact name
import { greet } from './module';
```

## 21. this Keyword

**Answer:**

```javascript
// 1. Global Context
console.log(this); // window (browser) or global (Node.js)

// 2. In Object Method
const person = {
  name: "John",
  greet() {
    console.log(this.name); // "John" (this refers to person object)
  }
};
person.greet();

// 3. In Regular Function (inside method)
const person2 = {
  name: "Jane",
  greet() {
    function inner() {
      console.log(this); // window/global (not person2!)
    }
    inner();
  }
};
person2.greet(); // logs window

// 4. Arrow Function (lexical this)
const person3 = {
  name: "Bob",
  greet() {
    const inner = () => {
      console.log(this.name); // "Bob" (inherits this from outer scope)
    };
    inner();
  }
};
person3.greet();

// 5. Constructor
function Person(name) {
  this.name = name; // this refers to new object being created
}

const john = new Person("John");

// 6. call, apply, bind
function introduce() {
  console.log(`I'm ${this.name}`);
}

const user = { name: "Alice" };

introduce.call(user); // Explicit this - "I'm Alice"
introduce.apply(user); // Same as call
const boundIntro = introduce.bind(user);
boundIntro(); // "I'm Alice"

// 7. Event Handler
const button = document.querySelector('button');
button.addEventListener('click', function() {
  console.log(this); // The button element
});

// But with arrow function
button.addEventListener('click', () => {
  console.log(this); // window (lexical this)
});
```

## 22. Promises and Callbacks

**Answer:**

```javascript
// Callback - Old way of handling async
function fetchDataCallback(callback) {
  setTimeout(() => {
    callback(null, "Data loaded");
  }, 1000);
}

fetchDataCallback((err, data) => {
  if (err) console.log("Error:", err);
  else console.log(data);
});

// Callback Hell (Pyramid of Doom)
```

## 24. Deep Copy vs Shallow Copy

**Answer:**

```javascript
// Shallow Copy - Only copies top level
const original = {
  name: "John",
  address: { city: "NYC" }

// Method 1: Using JSON (has limitations)

// Method 2: Recursive function
function deepCopy(obj) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof Array) return obj.map(item => deepCopy(item));
  
  const copy = {};
  for (let key in obj) {
    if (obj.hasOwnProperty(key)) {
      copy[key] = deepCopy(obj[key]);
    }
  }
  return copy;
}

const deep2 = deepCopy(original);

// Method 3: Using structuredClone (newer)
const deep3 = structuredClone(original);
```

## 1. Authorization vs Authentication

**Answer:**

```
Authentication: WHO are you?
Authorization: WHAT can you do?
```

### Authentication

```
Process: Verifying user identity
Method: Username/password, fingerprint, 2FA, OAuth
Result: User is confirmed to be who they claim
Example: Login with email and password
```

### Authorization

```
Process: Verifying user permissions
Method: Role-based access control, permissions
Result: User is allowed/denied to access resource
Example: Admin can delete users, regular user cannot
```

### Example Flow

```
1. User enters credentials (Authentication)
   → System verifies: "Yes, you are John"
   
2. User tries to access admin panel (Authorization)
   → System checks: "Are you admin? No, access denied"
```

## 5. PUT vs POST vs PATCH

**Answer:**

```javascript
// POST - Create
// URL: /api/users
// Body: { name: "John", age: 30 }
// Response: { id: 1, name: "John", age: 30 } (created resource)
// Idempotent: No (creates new resource each time)

// PUT - Replace entire resource
// URL: /api/users/1
// Body: { name: "Jane", age: 25 } // Must include all fields
// Response: { id: 1, name: "Jane", age: 25 }
// Idempotent: Yes (same result every time)
// Note: If field not provided, it's set to null/default

// PATCH - Partial update
// URL: /api/users/1
// Body: { name: "Jane" } // Only changed fields
// Response: { id: 1, name: "Jane", age: 30 } (merged with existing)
// Idempotent: Yes (same result every time)
// Note: Only updates provided fields

// Example differences:
const user = { id: 1, name: "John", age: 30, email: "john@email.com" };

// PUT replaces everything
PUT /api/users/1
{ name: "Jane", age: 25 }
// Result: { id: 1, name: "Jane", age: 25, email: null }

// PATCH updates only provided fields
PATCH /api/users/1
{ name: "Jane", age: 25 }
// Result: { id: 1, name: "Jane", age: 25, email: "john@email.com" }
```

## 6. OAuth 2.0

**Answer:**

```
OAuth 2.0 - Authorization protocol for delegated access

Process:
1. User clicks "Login with Google"
2. App redirects to Google's login
3. User logs in to Google
4. Google redirects back with authorization code
5. App exchanges code for access token
6. App uses access token to access user's data

Grant Types:
- Authorization Code: Web applications (most common)
- Implicit: SPAs (deprecated, use PKCE)
- Client Credentials: Server-to-server
- Resource Owner Password: Legacy, not recommended
- PKCE: SPAs with code challenge (recommended)

Tokens:
- Access Token: Used to access protected resources
- Refresh Token: Used to get new access token
- ID Token: Contains user information

Key Components:
- Resource Owner: User
- Client: Your application
- Authorization Server: Google, GitHub, etc.
- Resource Server: API server with user's data
```

```javascript
// Performance Testing in Automation

async function detectPerformanceBottlenecks() {
  const browser = await chromium.launch();
  const page = await browser.newPage();

  // Method 1: Measure Navigation Timing
  await page.goto('https://example.com');
  
  const navigationTiming = await page.evaluate(() => {
    const timing = window.performance.timing;
    return {
      dns: timing.domainLookupEnd - timing.domainLookupStart,
      tcp: timing.connectEnd - timing.connectStart,
      ttfb: timing.responseStart - timing.navigationStart,
      download: timing.responseEnd - timing.responseStart,
      domProcessing: timing.domInteractive - timing.domLoading,
      domComplete: timing.domComplete - timing.domInteractive,
      pageLoadTime: timing.loadEventEnd - timing.navigationStart
    };
  });

  console.log('Navigation Timing:', navigationTiming);
  
  // Assertions
  expect(navigationTiming.pageLoadTime).toBeLessThan(3000); // Load in 3 seconds

  // Method 2: Measure Resource Timing
  const resourceTiming = await page.evaluate(() => {
    const resources = window.performance.getEntriesByType('resource');
    return resources.map(r => ({
      name: r.name,
      duration: r.duration,
      size: r.transferSize,
      type: r.initiatorType
    }));
  });

  console.log('Slow Resources:', resourceTiming.filter(r => r.duration > 1000));

  // Method 3: Monitor Network Requests
  const slowRequests = [];
  page.on('response', response => {
    if (response.timing().responseEnd - response.timing().requestStart > 2000) {
      slowRequests.push({
        url: response.url(),
        method: response.request().method(),
        duration: response.timing().responseEnd - response.timing().requestStart
      });
    }
  });

  await page.goto('https://example.com/dashboard');
  
  if (slowRequests.length > 0) {
    console.log('Slow Network Requests:', slowRequests);
    throw new Error(`Found ${slowRequests.length} slow requests`);
  }

  // Method 4: Measure Core Web Vitals
  const webVitals = await page.evaluate(() => {
    return {
      // Largest Contentful Paint
      lcp: new Promise(resolve => {
        new PerformanceObserver((list) => {
          const entries = list.getEntries();
          const lastEntry = entries[entries.length - 1];
          resolve(lastEntry.renderTime || lastEntry.loadTime);
        }).observe({ entryTypes: ['largest-contentful-paint'] });
      }),
      
      // First Input Delay
      fid: new Promise(resolve => {
        new PerformanceObserver((list) => {
          resolve(list.getEntries()[0].processingDuration);
        }).observe({ entryTypes: ['first-input'] });
      }),
      
      // Cumulative Layout Shift
      cls: new Promise(resolve => {
        let cls = 0;
        new PerformanceObserver((list) => {
          for (const entry of list.getEntries()) {
            if (!entry.hadRecentInput) {
              cls += entry.value;
            }
          }
          resolve(cls);
        }).observe({ entryTypes: ['layout-shift'] });
      })
    };
  });

  console.log('Core Web Vitals:', webVitals);

  // Method 5: Measure JavaScript Execution Time
  const jsExecutionTime = await page.evaluate(() => {
    const start = performance.now();
    // Simulate heavy computation
    for (let i = 0; i < 1000000; i++) {
      Math.sqrt(i);
    }
    return performance.now() - start;
  });

  // Method 6: Generate Performance Report
  const perfReport = {
    timestamp: new Date(),
    pageUrl: page.url(),
    navigationTiming,
    resourceTiming,
    slowRequests,
    jsExecutionTime
  };

  console.log(JSON.stringify(perfReport, null, 2));
```

```javascript
function countVowelsAndConsonants(str) {
  let vowels = 0;
  let consonants = 0;
  const vowelSet = new Set(['a', 'e', 'i', 'o', 'u', 'A', 'E', 'I', 'O', 'U']);

  for (let char of str) {
    if (vowelSet.has(char)) {
      vowels++;
    } else if (/[a-zA-Z]/.test(char)) {
      consonants++;
    }
  }

}
```

```javascript
      count++;
    } else {

  }
```

```javascript
function groupAnagrams(words) {
```

```javascript
function findMissing(minLength = 1, maxLength = 20, arraySize = 10) {
```

```javascript
function longestSubstring(str) {
  let maxLength = 0;
  let start = 0;
  const charIndex = {};
  
  for (let end = 0; end < str.length; end++) {
    const char = str[end];
    
    if (charIndex[char] !== undefined && charIndex[char] >= start) {
      start = charIndex[char] + 1;
    }
    
    charIndex[char] = end;
    maxLength = Math.max(maxLength, end - start + 1);
  }
  
  return maxLength;
}
```
